# v1.1.0 Release Notes Draft

Date: 2026-07-30

## Summary

v1.1.0 prepares TheTattooCore for the next release candidate with stronger public profiles, search, messaging, booking, mobile/PWA behavior, admin operations, payment safeguards, and release verification.

## Member-Facing Improvements

- Improved artist and studio profile presentation, shop/profile links, and follower/following route behavior.
- Expanded search and discovery filters with tighter privacy controls and bounded pagination.
- Strengthened direct messages, notifications, read state, and blocked-user handling.
- Expanded booking lifecycle support, calendar download safety, schedule overlap protection, and input validation.
- Improved mobile safe-area behavior, PWA manifest/service worker checks, and narrow/tablet viewport coverage.
- Kept public help, support, safety, and legal surfaces aligned with launch policy.

## Operational Improvements

- Added CSP Report-Only readiness and a local observation harness.
- Added no-store response helpers and isolate-local rate limiting for selected sensitive endpoints.
- Strengthened admin authorization, owner protections, mail testing, audit integrity, input validation, merchant actions, and idempotency.
- Added native push outbox and scheduled Worker plumbing while keeping global delivery disabled.
- Expanded payment, checkout, webhook, refund, dispute, seller payout, and release-gate verification.
- Added Phase 8.5 cross-platform QA documentation and docs-readiness guard alignment.

## Migration Notes

Nine migrations are included for messaging, notifications, booking lifecycle, booking overlap protection, admin policy hardening, and admin operation idempotency. Apply only through the controlled migration runbook.

## Known Limitations

- Physical iPhone, iPad, Android phone, and Android tablet certification is not complete unless the user supplies separate evidence.
- Firefox and Safari certification is not complete.
- CSP remains Report-Only.
- Rate limiting is isolate-local rather than globally durable.
- Seller payout release remains disabled.
- Native push delivery remains disabled until exact-build delivery evidence passes.
- Native/store distribution remains uncertified; the strict `native-store-distribution` evidence guard must pass before Android/iOS tester or store distribution readiness is claimed.
- Production v1.0.6 follower/following 404 mismatch must be verified after v1.1.0 deployment.

## Release Tagging

Do not create `v1.1.0` until:

1. `release/v1.1.0-rc` is reviewed.
2. Controlled migrations are applied successfully.
3. Deployment is separately authorized and completed.
4. Live post-deployment smoke passes.
5. Remaining physical-device/browser gaps are accepted or completed.
