## Rate-Limit Decision

Decision: accept isolate-local rate limiting for v1.1.0 with documented limitation.

Current implementation is in-memory per Worker isolate, keyed by authenticated user when available or by validated `cf-connecting-ip` fallback. It rejects comma-separated/spoof-shaped IP values and falls back to `anonymous` when a trusted platform IP is absent. Buckets are bounded and pruned.

Limitation: this is not globally durable and does not coordinate across Cloudflare isolates. It is sufficient as a v1.1.0 abuse dampener because the sensitive mutation paths also have authorization, idempotency, payment preflight, or service-only gates. A durable rate-limit design remains a post-release hardening item.

## CSP Decision

Decision: keep CSP Report-Only for v1.1.0.

`TTC_CSP_ENFORCE_ENABLED=true` is the only enforcement switch. Production must leave the variable unset or `false` until sanitized Report-Only production violations are collected and reviewed. Current policy still includes `unsafe-inline` for Next.js/runtime style compatibility, and no in-repo production CSP report endpoint exists.
